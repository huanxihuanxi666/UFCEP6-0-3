 Submission Supplement

This folder is a marker-facing supplement. It does not replace the existing BPMN, forms or worker source code.

 What was checked

- 8 BPMN model files can be parsed as XML.
- 26 Camunda form files can be parsed as JSON.
- The worker project contains 8 production Java classes and 4 Java test classes, plus `pom.xml` and the H2 database file.
- The Postman mock collection, environment file, API integration BPMN and its two forms are present.

 What this folder adds

1. 603_Release2_Submission_Readiness_Audit.docx - distinguishes verified implementation from missing submission evidence.
2. 603_Live_Demonstration_Evidence_Capture_Guide.docx - exact order for collecting normal and exception-path screenshots after the already-working services are running.
3. 603_Release2_Requirements_Traceability_Matrix.docx - maps requirements to BPMN, forms, worker code and proof.

 Before handing in

1. Export the master, five operational subprocesses, strategy BPMN, SR and SD diagrams to PDF.
2. Follow the evidence guide and place the seven captured screenshots in this folder.
3. Create the final group presentation deck and cite the evidence IDs E1-E7 on the relevant slides.
4. If your group uses GitHub/GitLab, add the repository URL and commit identifiers to the final deck or an appendix.

The existing worker code should be retained as it is. The purpose of this supplement is to make its value visible to the marker.
